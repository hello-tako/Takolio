The E2E covers all 12 required flows: open console → sign in as Super Admin → Overview from the local
backend → every primary screen → user search, detail and audited reveal → billing → AI usage → recipes
plus an editorial review → system health → audit history → role restrictions (content editor:
hidden navigation, denied page, and API 403 for direct calls, forged headers, missing CSRF, and
valid-CSRF-but-unauthorized) → logout, after which the API returns 401. It also covers owner refusal
and the mobile drawer.

## 14. Remaining external integration blockers

1. Cloudflare Access is not verified against a real tenant. The verifier is tested with local keys only.
2. There is no production SUPER_ADMIN bootstrap procedure. The CLI is local-only by design.
3. The production migration workflow allow-list must add 0042 through a reviewed PR. After apply, pin the
   0042 hash in `tests/fixtures/migration-sha256.json`.
4. The runtime does not write `ai_requests` (`LOG_AI_REQUEST` is unused). AI metrics are `partial`, and AI
   retries are `unavailable`.
5. Remote adapters (Cloudflare analytics/queues/D1 metrics, GitHub releases, payment-provider
   reconciliation) are interface-only and report `unavailable`.
6. Recipe publication into canonical authority is not implemented. V1 writes an editorial ledger only.
7. Independent security review and a staging penetration test are still outstanding.
