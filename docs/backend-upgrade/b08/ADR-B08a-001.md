# ADR-B08a-001 - Bounded Worker request telemetry

Date: 2026-10-11 JST. Status: LOCAL_CODE_CANDIDATE.
Base HEAD: `1963c469e2e3bd4819cda6bb9ef8162101ad523a`.
Scope: HTTP request completion telemetry only; B08a/b implementation and B08c read-only triage.

## Decision and privacy boundary

Replace the Worker entrypoint's raw request path log with one explicit JSON event
per completed HTTP request. `buildRequestTelemetry` constructs an allowlisted
object rather than spreading caller input:

| Field | Allowed value |
| --- | --- |
| event / schemaVersion | `http_request` / `1` |
| requestId | Server-generated UUID v4 |
| method | GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS, or OTHER |
| routeTemplate | Non-wildcard template in the developer-registered `app.routes` set, or UNMATCHED_OR_GATED |
| status | HTTP integer 100-599; invalid measurement becomes 500 |
| durationMs | Finite integer clamped to 0-86,400,000 |
| environment | production, staging, development, or unknown |
| errorClass | Allowlisted status class; unexpected errors use INTERNAL_SERVER_ERROR |

Registered route templates can include `:id`; substituted IDs never enter this
event. Hono's `*`, `/*` and other wildcard paths map to UNMATCHED_OR_GATED. This
also covers SPA, CORS preflight and requests stopped before route dispatch.
The event contains no raw path/query, request body, email, OTP, token, household,
user, image key/base64, provider payload, error text or stack.

A server UUID is assigned to the Hono `requestId` context before downstream
middleware. It is also used by the existing bounded global-error diagnostic,
so that diagnostic cannot inherit a caller-controlled correlation payload.
Existing response `X-Request-Id` values matching `[A-Za-z0-9_-]{8,64}` remain
caller-visible for compatibility, including `frontend_test_123`. Invalid values
are replaced with the server UUID. A valid caller ID can encode private content;
therefore it is never reused in logs. With a caller-supplied compatible ID, the
response ID and logged UUID intentionally differ. There is no logged mapping
between them. Without a caller ID, response and log share the server UUID.

Telemetry sink exceptions are contained. Existing health/API/CORS/SPA routing,
intentional HTTPException handling, development error bodies, queue consumer,
scheduler, environment flags and resource bindings retain their behavior.

## Evidence and limits

Focused offline validation: 4 files / 59 tests PASS (21 helper, 6 Worker
entrypoint, 17 existing CORS, 15 existing health). Scoped ESLint and both strict
worker/unit TypeScript checks PASS. The entrypoint integration uses the existing
`.mjs` test pattern to avoid importing mixed DOM/Workers ambient types.

Receipts and final file hashes live in
`.artifacts/backend-program-20261011/b08-telemetry/metadata.json`.
The coordinator owns full checks and final commit receipts.

This packet does not certify provider calls, remote resources, seven-day SLOs,
p95 production latency, incident alert delivery or complete repository-wide
log privacy. Other business log producers and platform invocation logs need
separate review; existing queue/scheduled output is outside this change.
Duration is one Worker wall-clock request measurement, not DB/provider phases,
CPU time or an SLO claim. No monitoring export or external collector is enabled.

## B08b remaining observability gates

1. Review each existing business/platform log producer for sensitive fields;
   do not infer whole-system privacy from the request event tests.
2. Collect approved staging events for request/error volume, route latency and
   status-class counters. Use only the bounded fields above, and keep response
   IDs outside analytics. Pin the deployed SHA and measurement interval.
3. Establish route-specific targets and sample sufficiency before calculating
   p95; document invocation sampling and retention. Production logs currently
   sample at 1.0 and staging at 0.1, unchanged by this packet.
4. Rehearse alerts with synthetic local/staging events and record actual
   operator delivery/recovery evidence. A seven-day production observation
   cannot be substituted with generated data or this local check.
