# ADR B04a-001: Governed provider injection, call admission and cancellation

Date: 2026-10-11 JST. Status: LOCAL_IMPLEMENTATION_PENDING_INDEPENDENT_REVIEW.

## Decision and ownership

Extend the existing QwenTaskRuntime rather than introduce a second router, queue, quota ledger or inventory writer. Keep the constructor's first two arguments and the existing Qwen model-role defaults. The optional third TaskRuntimeOptions argument accepts providerFactory, beforeCall and opaque callScope. Explicit injection supplies providers by existing governed model role and never silently falls back to a network provider when the factory returns undefined. No runtime flag, allowlist, model policy, pricing, provider cutover or paid call is authorized by injection.

Owned paths are types.ts, task-provider.ts, task-runtime.ts, providers/qwen.ts, focused provider tests and this ADR. Router/index exports, queue, routes, storage/migrations, config, dependencies, catalog, billing and authentication remain outside this checkpoint.

## Provider API and unchanged policies

RuntimeTaskProvider supplies providerId, vision, receiptScan, chat and getLastUsage. TaskProviderFactory receives role, physical model, capabilities and request timeout; credentials remain inside default Qwen construction. TaskProviderCallOptions preserves maxTokens, temperature, jsonMode and visionRepairInstructions while adding optional AbortSignal and absolute epoch-millisecond deadlineAt. QwenCallOptions remains a backward-compatible type alias.

Governance still decides allowed roles, bounded calls/output/context/operation tokens, schema validation, quality gate, same-role repair, controlled escalation and shadow admission. Usage logs identify the injected provider honestly while retaining governed model/prompt/pricing fields. Existing v1 normalization, defaults and label routing are unchanged. Scan V3 integration remains B03b B2.

## Cancellation and deadline

AIRuntimeRequest extends AICallControl with signal and deadlineAt. The entire operation shares one absolute deadline across primary, repair, retry, escalation and shadow; each attempt cannot reset it. Invalid deadlines fail before any call. Already-aborted requests fail before admission. The runtime races both admission and provider promises against a controlled cancellation signal and checks again before retry, schema-result publication and return. Adapter promises that ignore abort may finish, but cannot produce a returned value, success log or later provider invocation after cancellation. Pending promises receive rejection handlers, and timers/listeners are cleaned up.

Shadow inherits the original external signal, including after primary has returned, and the same absolute deadline. Each shadow also has its own control lifetime. Cancelling shadow cannot retract a completed primary, and shadow never writes inventory or consumes entitlement quota.

Qwen combines caller controls with its original provider timeout, propagates the signal to fetch, and fences late fetch/body completions before usage capture. Provider-owned timeout remains REQUEST_TIMEOUT/retryable=true. Caller abort is AI_CALL_ABORTED/retryable=false. An exhausted operation deadline is REQUEST_TIMEOUT/retryable=false. Abort reasons and payload details are not included in these errors. The existing queue timeout is not wired to the new caller controls here; route/queue propagation and cancellation CAS require B04b ownership.

## Dormant admission extension for B04b

beforeCall receives task, role, physicalModel, primary/repair/retry/escalation/shadow kind, attempt, opaqueScope, signal/deadline, inputBudget and maxOutputTokens. It is awaited before every provider invocation. Rejection produces bounded AI_ADMISSION_DENIED with retryable=false. A late hook completion after cancellation/deadline cannot invoke the provider. The runtime does not refund, reset, settle or fabricate a durable reservation; B04b owns those decisions.

inputBudget reports estimatedInputTokens, inputTokenBound:null and decoded imageBytesBound when safely measurable. URL image bytes and trusted provider input-token bounds remain unknown. Existing text/vision estimates are not conservative multimodal provider-token or paid spend bounds. A durable job budget cannot be certified from these estimates: B04b must require externally trusted model/vision bounds, immutable pricing and explicit reservation policy. The hook is dormant with no caller supplied and changes no production budget behavior.

## Validation and limits

Meaningful fixtures prove injected no-network execution, factory absence, truthful provider identity, bounded repair/escalation/retry, admission for all call kinds, sanitized admission refusal, cancellation before/during calls, ignored cancellation/deadline, stale repair, original shared deadline, late admission, late Qwen response/usage, shadow after primary and cleanup. Existing Qwen/provider governance tests remain required alongside scoped lint/strict TypeScript checks.

This checkpoint is CODE_COMPLETE_RUNTIME_ADAPTER_CANDIDATE only after independent review and coordinator full gates. Per-invocation budget ceilings still reset across queue deliveries. No durable per-job reservation, queue cancellation CAS, versioned Scan V3 runtime, real provider benchmark, staging or production certificate is implied. Existing provider usage storage remains request-adapter state; durable charge reconciliation is a later explicit job-budget responsibility.

Rollback removes the explicit factory/hook caller and uses the same existing Qwen defaults; new optional controls can remain available. No persisted schema/event/history changes exist in this packet.
