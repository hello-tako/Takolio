# ADR B06-001: Purchased selection and shared cooking allocation

Status: ACCEPTED_LOCAL_FIX_PENDING_FINAL_GATES. Base1963c469e2e3bd4819cda6bb9ef8162101ad523a.

Before-fix SQLite HTTP matrix reproduced10 failures: checked cannotBuy items imported
implicitly, explicit cannotBuy imported, and native committed batch response-loss
returned500. A later repeated cooking-line fixture found two native allocation
failures with sufficient stock. Legacy and dual Week, legacy/native inventory were
covered; preserve their actual quantity/source/FEFO versus legacyFIFO behavior.

Default purchased selection is checked && !cannotBuy. Explicit blocked selection
returns409 CANNOT_BUY before claiming a durable command. All quantity/unit/name
fields still come from the authoritative stored plan; extra client fields cannot
override them. This API continues full-item selection. Partial quantities and
substitutions require a separate versioned product contract and are not fabricated.

Native import catch reads the scoped completed command and exact request fingerprint
before returning its stored response with idempotentReplay. Invalid JSON, missing
success or negative/noninteger count returns503 DATA_INTEGRITY_ERROR. A lost D1
response never blindly repeats stock writes. Retain existing success shape and
command-replay policy, inventory projection and restricted tenant scope.

Native cooking shares per-lot planned quantities across all deduction lines.
Subtract earlier allocations from each FEFO lot before allocating the next line;
never allocate one lot twice beyond its remaining quantity. Insufficient response
reports prior-line remaining availability in the requested compatible unit. The
existing atomic lot commands, expected versions, command keys and history retain
authority. No scoring, catalog, migrations, client API or release flags change.

Tests preserve source/snapshot fingerprints, pack rounding after unmet demand,
selected imports, CREATE/CORRECT provenance, response-loss/replay, trigger rollback,
repeated physical unit lines, shortages, FEFO/FIFO and stale corrections. Rollback
must retain these correctness fixes and durable receipts; never restore the known
blocked-item import or over-allocation. Hosted D1 and a new partial-purchase UX remain
separate gates. Root source review and full local verification are required.
