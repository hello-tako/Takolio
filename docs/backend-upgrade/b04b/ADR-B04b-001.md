# ADR B04b-001: Dormant durable scan AI reservation kernel

Date: 2026-10-11 JST. Status: LOCAL_CANDIDATE; not an applied migration or production admission gate.
Base: 1963c469e2e3bd4819cda6bb9ef8162101ad523a.
Scope: `packages/db/src/scan-ai-budget.ts`, candidate SQL, focused SQLite tests and this ADR.

## Problem and existing authority

The task runtime bounds an individual operation. Queue redelivery, repair, escalation,
shadow and a crash can create more than one operation for a durable scan job. Existing
`scan_queue_jobs` provides the tenant/status/claim_token/claim_attempt/locked_at fence;
existing scan quota records represent user scan allowance, not provider spend.

B04a exposes `estimatedInputTokens` and `inputTokenBound=null`. An estimate, image-byte
limit, output setting, elapsed deadline or abort does not prove a complete provider input
or price ceiling. This kernel does not consume B04a's current admission DTO and is not
wired to a queue, router, provider, worker export, configuration or shared index.

## Decision

Use the current SQLite/D1 database and atomic batches, with two additive candidate tables:

- `scan_ai_job_budgets`: immutable policy per job and lane, tenant/scan/user binding,
  policy SHA-256, explicit maximum calls, total tokens and integer micro-USD.
- `scan_ai_call_reservations`: immutable reservation per job/lane/call key, descriptor
  and trusted-proof SHA-256, exact request digest, provider/model/task/kind, admitting
  lease provenance and full upper-bound token/spend charge.

`main` covers primary, repair, retry and escalation cumulatively across leases. `shadow`
has its own immutable limits and only accepts shadow descriptors. Both lanes stay separate
from user scan allowance and inventory; combining their operator spend totals is a future
reporting task. Each call charges one admission, all input plus output upper-bound tokens,
and worst-case price. A budget can be zero. New policy limits never replace an old policy.
All admitted reservations count forever in this candidate; it has no refund, settlement,
free-retry, deletion or reset API. Outcome remains `RESERVED_UNKNOWN` even when a provider
response is absent. Future observed usage can be recorded separately without erasing the
reserved ceiling.

The atomic batch first installs policy if absent, then conditionally inserts the reservation.
It checks the same immutable policy fingerprint and tenant, current job and scan processing
status, matching claim token and attempt, locked_at within the existing ten-minute lease,
nonfuture lock time, current household membership and active price validity. Aggregate
COUNT/SUM queries over the reservation primary scope enforce all three caps inside that
transaction. The unique job/lane/call key supplies admission idempotency. A competing
policy or call descriptor cannot change the winner's charge.

## Trusted input and pricing prerequisites

`createScanAIBudgetPolicy(serverProvider)` creates a private capability from validated,
reviewed operator policy. `createScanAICallProof(serverProvider)` creates a private capability
from a separate validated evidence record. Structural copies or serialized capabilities
cannot be used; Zod deep-clones the source before asynchronous hashing. Input changes after
creation cannot reduce a stored charge. These wrappers do not authenticate an arbitrary
function supplied by an HTTP client. Trusted server provider selection is a caller obligation.

The evidence record binds provider, physical model, actual task, kind and SHA-256 of the
complete outbound request. Input must carry a provider exact-tokenizer or certified upper
bound covering COMPLETE_PROVIDER_INPUT, including system/user/repair/context and vision
input. Output must carry verified provider-enforced max-token semantics bound to that request.
Evidence references and evidence-content hashes are required. Estimated/null input bounds,
local-timeout output enforcement and unbound records fail closed.

Pricing must carry VERIFIED provenance, provider/model/version/source digest, a bounded
validity interval, USD integer micro-USD rates for input/output per million tokens and a
fixed-call ceiling. COMPLETE_CALL_CHARGES means the trusted pricing owner has covered all
charges for that provider/model, including image surcharges or minimum charges in token
or fixed-call bounds. No exchange-rate assumption or unpriced provider surcharge is allowed.
A source URL, reviewed label or content digest does not by itself prove the pricing is true.
Real verified bounds/pricing providers do not yet exist in this checkpoint. Synthetic tests
exercise the contract only; they do not certify Qwen or another provider.

The worst-case micro-USD charge is computed as:

`ceil(inputBound * inputRate / 1000000) + ceil(outputBound * outputRate / 1000000) + fixedCallBound`

Use BigInt for multiplication and rounding, then convert only after the total is within the
1e12 exact storage cap. Each operand and combined token bound is validated. SQLite checks
integer types and matching reserved_tokens=input+output. Policy call count is capped at10000
and token/spend totals at1e12, keeping both SQL aggregates and JavaScript boundaries exact.

## Public candidate API and failure semantics

`reserveScanAICall(db,{policy,proof,lease,callKey})` performs no provider/network call.
It returns a reservation result or a sanitized bounded reason.

| Result | Network permission | Reservation behavior |
| --- | --- | --- |
| acquired=true / acquired | One future attempt may use this admission | Full ceiling committed |
| acquired=false / replay | No new attempt | Original descriptor and charge retained |
| acquired=false / response_unknown | No new attempt | Commit found after lost batch acknowledgment; charge retained |
| acquired=false / claim_lost_after_reserve | No attempt | Cancellation/new lease followed COMMIT; charge retained |
| CLAIM_LOST | No attempt | No new charge when admission is fenced before COMMIT |
| POLICY_CONFLICT / IDEMPOTENCY_CONFLICT | No attempt | Existing immutable policy/descriptor retained |
| BUDGET_EXCEEDED / EVIDENCE_EXPIRED | No attempt | No reservation added |
| DATABASE_UNAVAILABLE / DATA_INTEGRITY_ERROR | No attempt | Any potentially committed charge remains retained |

The descriptor digest includes job/lane/call key, immutable policy and trusted evidence.
Lease token/attempt is stored as admission provenance rather than changing the descriptor
on redelivery. A currently valid new lease can observe the old matching call only with
acquired=false. An old or cancelled lease is denied. A lost batch response is never turned
into fresh network permission even when a committed row can be read.

The caller must invoke at most once per acquired=true return, honor output/provider bounds,
and check current cancellation/lease immediately before invoking the provider. A database
commit and a remote network call cannot be one transaction: cancellation after the final
lease check may still race an in-flight request. Cooperative AbortSignal/deadlines plus the
existing fenced result writer must stop stale publication; physical external cancellation
is provider-dependent. This module does not claim exactly-once remote calls, physical abort,
provider enforcement or production cumulative budget enforcement.

Invalid policy/proof/lease/key throws only bounded `ScanAIBudgetError` codes. No raw Zod
issues, source content, images, OCR, prompts, provider payload, email or secrets are logged.
The tables retain only bounded metadata and hashes. The trusted policyReference, opaque
identities/provider/model/call keys must themselves be privacy-reviewed before integration;
the schema cannot prevent an integrator from supplying sensitive text as a nominal ID.

## Schema promotion, retention and rollback

`schema.candidate.sql` is outside `migrations` and is applied only to an isolated test database
on top of the existing migration ledger. It has no migration number. Coordinator promotion
requires an append-only numbered migration, clone/replay/FK/quick_check, deployment ordering,
reader compatibility, trusted evidence providers, provider boundary integration and operational
review. Current route/queue readers and current scan quota remain unchanged.

The candidate uses immutable update/delete triggers and RESTRICT foreign keys so unknown
spend survives accidental cleanup. Existing terminal job/scan cleanup is not compatible with
these retained references once promoted. Resolve explicit retention/legal access/export and
controlled archival semantics before applying this schema anywhere persistent; do not merely
remove the triggers or cascade-delete historical charges. There is no live database affected
by this checkpoint.

Rollback before promotion is stopping use of the dormant candidate. After eventual promotion,
disable new provider admissions while retaining budgets/reservations and expanded schema;
never reset charged counters, purge queue history or refund UNKNOWN reservations. A compatible
reader must understand old reservations even when candidate writer enablement is disabled.

## Local acceptance and remaining work

SQLite tests cover each cap, all call kinds, immutable policy, same-key descriptor conflicts,
concurrent same/different-key admissions, atomic rollback, response loss, crash without result,
new/stale/expired/cancelled lease, membership revocation before the batch, cancellation after
reserve, unavailable receipt read, tenant isolation, main/shadow separation, exact pricing,
overflow and rejection of estimated/unverified evidence. They snapshot user quota, scans/jobs
and stock authorities to demonstrate no unintended changes. No real AI/provider call is made.

Coordinator owns the final global checks and independent review. Passing local validation is
CODE_COMPLETE_BUDGET_CANDIDATE, not PROVIDER_BOUND_CERTIFIED, MIGRATION_APPROVED,
STAGING_CERTIFIED or PRODUCTION_APPROVED. Runtime integration remains blocked on complete
trusted input/output/cost bounds and retention compatibility.
