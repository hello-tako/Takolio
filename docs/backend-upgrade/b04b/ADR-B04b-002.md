# ADR B04b-002: Cancellation on the existing fenced scan ledger

Status: ACCEPTED_FOR_LOCAL_IMPLEMENTATION. Base1963c469e2e3bd4819cda6bb9ef8162101ad523a.

The coordinator owns scan-queue.ts, scans.ts, router.ts, the new queue-envelope
reader and corresponding tests. Keep existing queue, quota, inventory authority,
provider defaults and all applied migrations. Durable spend storage is a dormant
candidate with separate trusted pricing/token prerequisites (ADR-B04b-001).

Add POST /scans/:id/cancel under existing cookie/CSRF/tenancy guards. Cancellation
is allowed only for existing queued pending/processing scans in the authorized
household. It atomically changes the job and scan to existing failed states,
records bounded SCAN_CANCELLED, invalidates the claim token and releases a reserved
user scan allowance. Repeated cancellation returns the same successful meaning.
Ready/confirmed scans and synchronous scans without a queue intent return409;
foreign/missing scans return404. Cancellation never reverses an accepted scan or
inventory history. A successful result commit wins before cancellation and stays
ready; cancellation wins before commit and every stale result statement is fenced.

Abort in-flight work in the same isolate after the durable cancellation commit.
Another isolate cannot receive that local signal: durable fences prevent publication
and a fresh lease check before each governed primary/repair/retry/escalation/shadow
prevents subsequent calls. This does not promise immediate remote provider abort or
refund. Queue deadlines share one absolute75-second deadline with governed runtime
and adapters; ignored aborts cannot publish. Existing retry classification remains.

AIRouter receives optional runtime options without changing its existing first two
constructor arguments. No caller-supplied factory or candidate enablement is added
by production composition. Preserve v1 queue producers, response shape and mock
fixtures. Terminal cancellation is readable as failed/SCAN_CANCELLED by old readers;
old rollback code already refuses terminal failed scans/jobs and only re-arms
RESERVATION_EXPIRED. Retain cancellation tombstones under existing cleanup policy.

Tests must cover pending/processing cancellation, household isolation, repeat
cancel, completion winner, stale/ignored provider response, quota settlement once,
atomic rollback/response-loss and redelivery without another provider call.
No remote deployment or provider certification follows from local results.
