# ADR B03b-002: Reader-first version fencing

Status: ACCEPTED_FOR_LOCAL_IMPLEMENTATION. Base1963c469e2e3bd4819cda6bb9ef8162101ad523a.

Read legacy absent-version jobs as contract1. Add strict pure readers for versioned
V3 job/results, binding task, schema version and tenant identity. The existing v1
queue processor must reject V3/unsupported versions before claiming a job or any
state mutation. A v1 message carrying schemaVersion3 must never be accepted by
casting it to the v1 shape. Invalid typed IDs/tasks/version fail with bounded codes.

Existing scan HTTP routes accept absent or explicit X-Scan-Contract-Version:1.
V3 remains a disabled writer: return409 SCAN_CONTRACT_NOT_ENABLED before uploads,
quota, enqueue or legacy confirmation defaults. Unsupported/malformed headers
return400 SCAN_CONTRACT_VERSION_UNSUPPORTED. This truthful negotiation fence is
usable before a V3 writer, storage and compatible review client are certified.
The pure result reader retains V3 UNKNOWN/JPY and never calls legacy hydration.
No CORS opt-in is advertised until the writer/client checkpoint is complete.

This completes the safe reader boundary, not the full B2 writer/client feature.
V3 storage, new request fingerprint, provider DTO/prompts and client manual review
still require a coordinated integration packet; existing v1 rows are unchanged.
Reader-first code can be retained during rollback. Unsupported queue messages are
permanent failures and cannot consume quota/provider admissions through v1.
