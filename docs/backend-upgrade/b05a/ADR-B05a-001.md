# ADR-B05a-001 - Evidence-bound offline ingredient review manifests

Date: 2026-10-11 JST. Status: IMPLEMENTED_FOR_LOCAL_REVIEW.
Scope: B05a C1/C2 only. Implements ADR-033 without changing runtime authority.
Base receipt: 1963c469e2e3bd4819cda6bb9ef8162101ad523a. The coordinator records
final implementation and validation receipts separately.

## Problem and decision

The canonical candidate preserves 500 recipes and 6,766 source ingredient rows.
Its V1 projection includes 3,770 rows and excludes 2,996. The existing audit flags
2,860 exclusions and another 169 already-projected rows for transformation
review. The 1,395 provisional identities, unverified source content and blocked
nutrition cannot acquire authority from labels or free-form evidence strings.

Add a pure wrapper in `packages/recipes/src/ingredient-review-manifest.ts`.
Keep the existing schemas, authority compiler, source adapter, V1 projection,
unit definitions, release compiler, runtime hydrator and release gate unchanged.
All results carry `authorityScope=OFFLINE_REVIEW`, `runtimeAuthority=false` and
`finalRuntimeFingerprint=null`. No output is DATA_CERTIFIED, STAGING_CERTIFIED or
PRODUCTION_APPROVED.

## Source and release proof

`buildIngredientReviewSourceProof` accepts the canonical source manifest, exact
bytes for every declared file, an independently pinned source SHA, the certified
base release manifest and the caller's certified same-release ingredient ID set.
The function checks exact file cardinality and hashes, then calls the existing
`fingerprintRefreshArtifact`. It validates all recipe identities, unique source
positions and source occurrence keys. Candidate base release identity must match
and be reproducible through the existing `deriveReleaseId` implementation.
Existing source IDs must belong to the supplied certified ingredient set;
provisional IDs cannot be supplied as certified existing identities.

The helper copies every caller-owned byte buffer and the existing-ID set before
the first asynchronous hash. Independent review reproduced a mutable-buffer
TOCTOU in the first candidate; the regression now preserves the verified original
source coverage even if callers overwrite their input during hashing.

The returned frozen proof exposes only pinned metadata and counts. Its private
source data lives in a module-owned WeakMap. A structurally identical object,
modified manifest or unverified recipe array cannot impersonate this proof.
Synthetic source descriptors are accepted only through the explicit TEST_ONLY
classification. They cannot be used as canonical candidate manifests.

The certified release artifact and its ingredient ID set are trusted inputs
from the offline coordinator. This helper does not independently certify their
provenance, query D1 or verify remote release evidence. The recipe release ID
and source digest checks bind this trust; they do not substitute for it.

## Review and evidence contract

Manifest schema version 1 includes candidate source SHA, base release ID,
review manifest ID and normalized content SHA. Each of the following decision
sets must cover its complete source domain exactly once:

- Identity decisions use the existing `IngredientReviewDecisionSchema` and bind
  to the actual provisional concept and complete source-name set. Complete,
  evidenced decisions are validated through `compileReviewedIngredientAuthority`.
- Transformation decisions bind recipe ID, source position, complete source row
  SHA and original ingredient identity. Display text, optional identity and the
  original authority state are preserved. An offline decision does not mutate
  the canonical source or manufacture a promoted runtime line.
- Source-content decisions bind the exact recipe/URL/role occurrence, content
  SHA, observation time and explicit claims, including valid source positions.
  Structural URL validity alone cannot resolve this decision.
- Nutrition decisions bind the source nutrition SHA, servings and per-serving
  basis. Truthful null remains null. Blocked profiles remain blocked until an
  independent review supplies complete edible/absorbed quantities and an
  evidenced nutrient reference.

The manifest cannot contain its own evidence ledger. `auditIngredientReviewManifest`
receives a separate trusted evidence ledger. Each resolved review must match its
reviewer, timestamp, source SHA, base release, authority scope, subject digest and
exact decision digest. Identity basis/reference must also match. Duplicate
ledger IDs, reuse for another subject, stale content and TEST_ONLY/HUMAN_REVIEW
classification mismatches block proof. This is evidence binding, not a digital
signature or independent proof that a person reviewed external content. The
caller must supply genuine reviewed records; no record is invented here.

Physical quantity changes use existing `UNIT_DEFINITIONS` for exact g/kg and
ml/l conversions. Culinary, count, package, density or reviewed source
measurements require an ingredient-specific conversion, reference, factor and
applicability range bound by the transformation review. Missing quantities
remain unresolved. Process use retains its own lineage and scaling policy;
salt beds and frying medium never automatically become edible quantities.
Measured consumption must match a separately evidenced nutrition decision,
source row digest, absorption basis and nutrition evidence reference. Neither
transformation evidence nor source amount alone grants nutrition authority.

## Determinism and readiness

Normalized manifest hashing sorts decision sets and nested claims by stable
keys and uses the existing `canonicalJson`/`sha256Hex` helpers. The audit reports
expected/resolved coverage and transformation class counts; its own SHA covers
the full deterministic report. Reordering valid source files, recipes, decisions
and ledger records produces identical hashes and serialized results.

Empty, partial, stale, unresolved, contradictory or duplicate decisions remain
INCOMPLETE. A premature REVIEW_COMPLETE claim is explicitly blocked. Complete
synthetic proof remains TEST_ONLY. An identity preview is emitted only after all
review sets are complete; it carries its classification and OFFLINE_REVIEW scope
and never changes a source, master row, alias, runtime recipe or catalog release.
The review hash is an artifact digest, never a second runtime fingerprint.

The source's existing release readiness and four blockers remain authoritative:
RUNTIME_PROJECTION_LOSS, INGREDIENT_RECONCILIATION_INCOMPLETE,
SOURCE_CONTENT_VERIFICATION_INCOMPLETE and NUTRITION_EVIDENCE_INCOMPLETE.
The current release-check therefore remains EXPECTED_BLOCKED (exit 1).

## Consumer dependencies before B05c/B05d

| Consumer | Required proof before a separate cutover |
| --- | --- |
| Planner T02/T04 | Unresolved shopping demand is infeasible, never zero |
| Ranking/composer T03/T20 | Full ingredient restriction identity survives every exclusion |
| Shopping T05 | Only evidenced shopping demand; one shortage allocation; reviewed packaging |
| Cooking/inventory | Purchased/used quantities only; FEFO and event history unchanged |
| Recipe detail/UI | Original display text; unresolved quantity cannot become numeric confirmation |
| Servings | Per-channel proportional/fixed/unresolved policy |
| Nutrition | Independent edible/absorbed amount and nutrient reference; blocked/null preserved |
| Plans/favorites/locks/media | Immutable release lineage and compatible rollback readers |

Existing `projectV1ShoppingRequirements` remains conservative and cannot consume
new review manifests as runtime authority. A later owner must derive a separately
reviewed source projection, prove consumer compatibility and use the existing
runtime fingerprint/release machinery. No migration, hydration, source edit,
consumer adaptation, network fetching, release manifest or deployment belongs
to B05a.

## Validation and pilot handoff

The owned tests use explicit TEST_ONLY fixtures and independently exercise file
and source digests, partial/duplicate decisions, evidence binding, fake promotion,
conversion ranges and units, anonymous evidence claims, nutrition coverage and
input-order determinism. A real-source test reconstructs 500 recipes, 1,395
provisional concepts, 6,766 lines, 1,102 source occurrences and 500 nutrition
profiles from the unchanged canonical bytes.

Raw local validation logs are under `.artifacts/backend-b05a/`; the coordinator
records final counts, command exits and hashes. Existing deterministic audit and
release checks remain separate from review proof. B05b uses `PILOT.md` to collect
real reviewer assignments and evidence. No deadline or cost is inferred before
pilot throughput is measured.

## Alternatives and rollback

Free-form evidence embedded in a decision is rejected as self-asserted review.
A new parallel resolver or compiler is rejected because it would split authority.
Changing the source to clear blockers would erase provenance and is out of scope.

Rollback stops use of this offline schema version and retains its review artifacts
for audit. No D1 state, source history, live event or runtime authority changes.
