# ADR B07-002: Bounded OpenAPI candidate from existing Zod contracts

Status: ACCEPTED_FOR_LOCAL_IMPLEMENTATION. Base1963c469e2e3bd4819cda6bb9ef8162101ad523a.

Generate a deterministic OpenAPI3.1 candidate for the existing modern planner
create/current/get/regenerate endpoints using existing executable request/response
Zod schemas. Do not modify those routes or invent a legacy Week response schema.
Use a small offline translator tied to the locked Zod3 representation rather than
adding dependencies. Unsupported node types throw and fail generation. Refinements,
transforms and exact decimal semantics remain in the executable source and are
marked x-runtime-validation; OpenAPI structural validation alone is not sufficient.
Never claim JSON Schema captures every Zod semantic constraint.

Input default values describe existing server behavior. Consumer types re-export
existing input/output types; no generated client changes or runtime wiring. Current
plan response is nullable; by-ID is a direct DTO. Auth/feature/CSRF/idempotency/revision
status tables are documented from actual adapters. No pagination is invented for
endpoints that lack it. Candidate includes exact source SHA256 and no timestamp.
Check mode fails if saved bytes drift. Source hash includes domain schema dependencies,
route adapter and generator, so any relevant change requires deliberate regeneration.

This starts the B07b pipeline for a bounded vertical slice; coverage of all catalog,
scan/inventory/Week/billing routes is a later explicit packet. Hand-authored production
handlers and existing Zod runtime validation remain authoritative. No dependency,
API behavior, persisted data or UI change occurs. Rollback stops consuming the
candidate. Local schema generation is not a hosted API/client certificate.
