# ADR-B07-001: Extract legacy Week read application service

Status: ACCEPTED_FOR_LOCAL_IMPLEMENTATION. Base 1963c469e2e3bd4819cda6bb9ef8162101ad523a.

Extract the existing /week/current and /week/plans/:id read path into a typed
repository and application service. Snapshot parsing and legacy relational
hydration move with it; existing route exports remain compatible. Keep exact SQL,
query ordering, cache publication, normalization/defaults and response bodies.
The route continues auth/tenancy/error/status serialization. No shopping command,
write, migration, scoring, data release or modern planner change belongs here.

Snapshot reads require one plan query, current adds one latest-ID query. A legacy
snapshotless read requires four plan/children queries plus the existing lazy recipe
authority if needed; no per-slot database lookup. D1 remains authoritative and KV
cannot resurrect a missing plan. Source snapshots remain immutable after stock or
catalog changes. Preserve historical normalization rather than silently tightening
old persisted data during this refactor. Any quality semantics belong another ADR.

Contract tests pin query count, real cookie tenant isolation, exact persisted
snapshot response, legacy fallback, no-plan/foreign/error/cache-failure paths.
Existing Week migration/replay/security/planner/inventory suites remain required.
Independent comparison against HEAD1963 covers six read/error/cache cases plus
ten day-normalization inputs: exact bodies, SQL/bindings/query order, cache TTL
and lazy catalog behavior match. The intentional observability difference replaces
raw D1 exceptions with the bounded week_plan_read_failed event.
Worker-only changes must not alter web assets under identical build inputs.
Rollback restores the compatible old adapter; no state or schema changes exist.
