## Decision and boundaries

Use raw D1 batches and dedicated OTP claims/assertions. Alternative read-compare-
conditional-counter updates cannot bound concurrent comparisons. Reusing inventory
claims or adding a new datastore adds authority without solving the auth boundary.
An account-wide HMAC request registry detects purpose/operation/body reuse; budget
scopes remain normalized-account+purpose. All persisted request fingerprints are
keyed HMACs of validated semantic payload; no raw code/password/email or secret.
Expected digests retain v1/v2 compatibility and never authorize a legacy challenge
without a strict issuance receipt. A1 issues for existing pinned principals and
synthetic unknown accounts; guarded registration creation is a later integration.

Capture integer unixepoch seconds in a transient command claim once per batch.
Key parser uses a DB epoch read and the reservation rechecks age/skew against the
captured claim time. Every required effect is claim-bound and followed immediately
by a CHECK assertion on changes()==1; zero required writes abort the same batch.
Revocation permits0..N and instead asserts no old active sessions before new insert.
Claims/assertions are removed within that transaction. Lost responses do not prove
rollback; persisted owner/ticket prevents repeated comparison or effects.

Policies:5new admissions per rolling900seconds, fifth sets900second lock but remains
eligible to finalize; issuance60seconds, challenge600seconds, ticket30seconds.
Window uses admitted_at>now-900 and <=now; now>=deadline/expiry is ineligible.
Server timestamp key <13digit epochMillis>:<32lowercase hex random>,1800second age,
30second future tolerance, receipt retention>=86400seconds. Missing keys get a fresh
server-time cryptographic key, with each no-key retry charged as a new operation.
Client will use explicit no-key-first bootstrap until issuance supplies server epoch;
no /config or client edits in A1. Future authenticated routes own Origin/Turnstile,
password checks and guest-transfer policy before calling this dormant kernel.

Admission spends budget before delivery/readiness/principal denial. Missing,
pending, rejected, unknown, used and expired challenges produce unavailable without
expected comparison; accepted eligible synthetic challenges compare but can never
succeed. Thus known/unknown scopes have the same budget and429 metadata even when
mail lifecycle differs. This is accounting parity, not timing indistinguishability.
Readiness outcomes must remain generic when future routes expose them.

Same issuance key never dispatches again, including unknown/pending. Fresh explicit
issuance after durable cooldown/no lock may supersede the old generation; late old
acceptance cannot activate replacement. Issuance-key replay returns in_progress
for issued receipts even after terminal delivery; A2 must map final delivery/expiry
metadata to its polling/UI contract before exposure. Accepted/rejected/unknown are terminal for
adapter completion, without callbacks/status reconciliation. Actual send work is
outside transactions; A1 exposes reserve/record hooks but performs no provider calls.

Legacy initialization lazily sums all retained rows, including used/superseded,
clamps each attempt to0..5 and total to5, imports accounting at init-time once and
preserves max existing lock. Five imported failures impose a one-time900second lock.
Preserve recent legacy issuance cooldown. This conservative over-count cannot
reconstruct exact rolling failure times. A1 changes only strict authority tables;
legacy readers remain untouched until integration performs a reviewed cutover.

No foreign-key cascade from users/accounts/auth_otps to registry/scopes/accounting.
Deleting/recreating principal or cleaning legacy challenges does not refund budget.
No new cleanup is scheduled in A1; at least24hour receipts must be retained and key
horizon enforced before later explicit pruning. Scope HMAC secret rotation is a
separate operational decision; fail closed if secret/database unavailable.

Success effects: registration activation+consume+session; login verify consume only;
preliminary reset proof outcome only, fixed original900second proof expiry, no consume
or session; final reset consume+password+revoke0..N+new session+durable outcome. Pin
account id/user id throughout; membership/existence is required for new session.
Raw session credential is returned only from a newly acknowledged commit; matching
completion replay supplies sessionRequired, never a new token or cookie. Preliminary
replay returns original proof metadata and cannot renew expiry.

Fingerprint binds semantic operation/purpose/body and code/password. Nonempty
register migrateFromHouseholdId is explicitly deferred before registry/admission/
comparison, returning unavailable without consume/activation/session. A2 owns
authorized guest transfer and its new payload/key contract.
Generated challenge/password salt/session material are excluded so replay is stable.
Generation/challenge chosen by first registry claim remain immutable; later same-key
replay cannot bind to a new generation. Per-purpose/operation reuse conflicts409.
No arbitrary caller-provided SQL or effects; SQL CHECK plus typed mapping prevents
login verification being used to grant a session.

## Verification and limits

Observe the actual dormant kernel's verifyOtpDigest calls under20/100racers, same
key racers, fifth-candidate success, stale generation, crash/lost-response, exact
boundaries, legacy import, principal recreation and constraint/required-zero faults.
Replay old/new migrations, FK/quick_check and isolated local Wrangler D1 apply/gate.
Full local gates and independent review precede checkpoint. SQLite/local D1 PASS
cannot certify hosted D1 or strict protection while legacy routes remain active.
A2 integrates all auth/client paths with guarded registration creation and cleanup;
separate staging D1 proof and named hardened rollback precede release. PayOS,
recipes/planner/inventory, config/workflows/dependencies and remote resources remain
outside this slice. Migration expands only; never drop tables or restore old unsafe
admission paths as rollback.
